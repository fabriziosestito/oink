# Publishing the documentation

These pages use plain Markdown, relative page links, and YAML front matter.
They follow the overview, reference, and architecture layout used by documentation
sites such as [Docusaurus](https://docusaurus.io/docs/category/guides).
There are no React components or theme-specific imports in the content.

## Docusaurus

Use this repository's `docs/` directory as the documentation plugin's content
path. Enable an autogenerated sidebar to use folders as categories.
`sidebar_position` fields set page order, and `reference/_category_.json` labels
the reference group.

```javascript
// sidebars.js in the future site project
export default {
  docs: [{ type: 'autogenerated', dirName: '.' }],
};
```

See the [autogenerated sidebar guide](https://docusaurus.io/docs/sidebar/autogenerated)
for the matching conventions. Links between pages include `.md` extensions so
Docusaurus can resolve them as document links. This repository does not yet
include a site installation, theme, build, or deployment workflow.

## Other generators

MkDocs and similar generators can also read the Markdown files.
Define their navigation from the [index](index.md); Docusaurus sidebar metadata
is optional for other tools. Keep page links relative when moving the content.

## Maintenance

Update the relevant reference page when changing an exposed function or YAML field.
Document argument types, defaults, returns, errors, and side effects together.
Keep architecture descriptions separate from user instructions and future designs.

The engine tests compile and execute the complete Ink examples in these pages.
The small YAML blocks illustrate individual sections and are not all standalone
rulebooks. The overview includes a complete minimal rulebook and matching story.
